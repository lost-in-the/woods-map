# Changelog

## [Unreleased]

- An action whose name implies no model event (a `show`, an `edit`, a custom action) no longer draws a model save in its Across containers view or its `.mmd`. The map used to fall back to the model's first lifecycle chain, so an unrelated action showed a save and an INSERT it was never said to make. That lifecycle now appears below as a "Related lifecycle", labelled as not a step of the action. `create`, `update` and `destroy` still draw their save.
- The reading trail keeps each page's full address, path and query, so returning through it restores the investigation (entry, pins, hops, generation, lens, range) instead of the bare page. The address never includes a `token`. Entries stored as a bare path by an earlier version still draw.
- The Schema tab and the ERD say what the evidence means.
  - **Defaults:** a column whose index publishes only that a default exists says "exists, value not published" instead of "yes". A published value is shown as published, and an empty string, `false` and no default read differently.
  - **ER scope:** the model Schema diagram is labelled "model associations only", counts the distinct tables it draws, and links to the ERD for the database's foreign keys.
  - **Incoming keys:** a has_many or has_one shows the foreign key its table publishes to this one. Otherwise it says "unchecked" and why, instead of a dash.
  - **Delete behaviour:** the finding beside a Rails `dependent:` option says the database delete action is not published.
  - **ERD totals:** the graph analysis's typed table names (`table:x`) are resolved to the published table before the unmodelled count, so a table counts once. A name no published table answers to is listed as its own finding and stays out of the counts.
- The token sign-in field stays visible below 640px. It was styled as the file tree, which the responsive rules hide on a narrow screen, so a phone reader could not enter the token. It now has its own styling, unchanged at desktop widths.
- A hub's first impact view no longer opens every unit it reaches.
  - **Render-by-name unknowns:** the Unknown tab opens only the reached units that Woods' graph lists as having unresolved renders (`unresolved_render_count`, woods#837), through `Repository#units_with`. A generation from an older Woods, or a Woods without the summary, still opens every reached unit.
  - **Action templates:** the passages behind the unassigned-ivar rule find an action's templates through an index of the generation's view templates, built once per template list, instead of scanning every template for every action.
- A retained range is compared once per process, with Woods' `ReportCache` (woods#835) when the installed Woods has one. The impact page's lenses and pages, the unit diff and `?since=` views of one range share one comparison. Woods keys it on the payloads the range resolves to, so `gen:N`, a commit SHA and `now` naming one pair share it, and a new publish or prune is a new key. On a Woods without the cache, each view still compares.

- The Graph neighbourhood, the Schema ER and the Lifecycle sequence draw their Mermaid from Woods' own builders (`Woods::Diagrams`, woods#826) when the loaded Woods has them. The Index MCP server's `diagram` tool and `woods:diagram` answer from the same builders. The text is unchanged, byte for byte: `spec/woods_map/woods_diagrams_spec.rb` compares every unit, depth, direction, filter and event on the fixture and the 300-model index. A Woods without the builders keeps the map's own. An edge without a mechanism draws a plain arrow in both, never an empty label. The lanes and flowchart views, `?since=` marks, C4 views, the ERD, History and the Trail stay in the map.
- Pages stay usable on a large generation (measured on synthetic apps of about 4,600 and 10,300 units).
  - **One reader per generation:** the index reader, the dependency graph and what the map derives from them (the typed node lookup, file ownership, the identifier index, the unit listings) are built once per published generation and shared by the requests that pin it (`WoodsMap::GenerationSnapshot`), where every request re-parsed the graph and re-read every unit index. Derived values are frozen.
  - **Units index:** each type shows its first 100 units, by name, with its exact count and a link to `/woods/units?type=<type>`, which lists that type 500 a page.
  - **Long lists page:** a graph's list equivalent (300 edges a page) and an impact's affected units (300 a page) carry a pager that keeps the page's query. The affected list looks up its covering tests once instead of once per row.
  - **Mermaid text over 64 KB is not carried in the page:** a diagram over its drawing budget says its text is not carried and offers no copy (its `.mmd` answers 422 with the reason, as before); an unbudgeted one, such as the blast radius, copies from its `.mmd` route, from the panel and the Share menu. A hub's depth-2 neighbourhood or blast radius no longer carries megabytes of text, three times over. The full-screen graph links its `.mmd` like the Graph tab.
  - **Commit table and graph text:** the generation's commit table is parsed once per generation instead of on every Code, Graph and History page, and a neighbourhood builds its Mermaid text and node ids once per request (a hub's depth-2 graph built them twice).
  - **Impact rules and unknowns:** the unassigned-ivar rule's outcome and the "render by name" unknowns are kept per generation and reach (`GenerationMemo`); at a hub they read a passage for every reached action and nearly every unit of the generation.

- Correctness fixes across the unit and impact pages.
  - **Unknown action:** a Passage or Lifecycle URL naming an action the unit does not have answers 404 with the unit's actions as links (plain text on `.mmd`), instead of silently showing the first action.
  - **Impact by commit:** a SHA several retained generations recorded resolves (Woods: the commit's first capture as `from`, its last as `to`). A range whose endpoints are one generation says *Nothing changed*, and Woods no longer reads every unit to say so.
  - **Impact at scale:** the range's Changed and Affected lists render pages of 200 and 300 with previous and next links, opening on the page that holds a focused unit; the per-change *reaches* lookup is indexed once.
  - **Pre-change impact:** affected units are ordered nearest first, then by PageRank weight, so units nothing depends on (documentation that mentions the focus) no longer lead. Tests, the job rule and the Unknown tab now cover every unit within the depth, and unresolvable routes and volatile dependencies only the ones that name a unit in the radius, so the lens counts move with the depth. Each tab's tooltip says its scope.
  - **Diagrams over budget:** the Mermaid text folds under a *Mermaid text* disclosure instead of filling the page, and the `.mmd` link (which answers 422 above the budget) is left out while the copy stays.
  - **Graph Mermaid:** each unit is declared once, and the `focus` class the text applies is declared too.
  - **Routes tab:** the tab, the section header and the table count the same routes, including route units the controller's metadata omits.
  - **History tile:** churn says its window (`in 365d`); people counts the authors of the window from the commit table, or says *top N contributors* when only Woods' per-file list is available.
  - The graph page no longer calls itself full-screen: it keeps the bar and crumbs, with the canvas filling the viewport below them.
- Dependents counts say what they count. The impact page's focus row counts the distinct typed units with an edge to the unit in this generation's graph ("6 typed units"). The hub notes, wherever they appear, carry graph_analysis' own per-identifier count ("hub, 19 dependents by identifier"). The two used to sit side by side with no label and read as a contradiction.

- Search and freshness fixes.
  - **Code search** asks Woods to read up to every unit of the generation (`max_scan:`, when this Woods accepts it) instead of stopping at the MCP scan budget. An incomplete search now says why it stopped and how much it read, for example "stopped after reading 500 of 8000 units' source (scan budget)". It no longer claims to have searched every unit, the empty state no longer suggests code search from code search, and the info tip names the stop reasons it promises.
  - **Name search** puts the exact name first, then exact short names (the last `::` segment, a table's name, a route's path), then prefixes, then other matches. It merges literal prefix, short-name, table and route searches so a broad query cannot push the exact name or its table off the page, in the same order on every generation.
  - **Path search** names the units that own each file.
  - **Freshness** runs Woods' quick check once per index and generation for 30 seconds instead of on every request. The bar says "no drift seen" when Woods' new coverage shows no drift in what it read, and links to a freshness row on the status page with the coverage, Woods' reasons and next steps in plain words.
- Navigation and the files sheet at any size of index and any width.
  - **The file tree is no longer in every page.** The sheet fetches it the first time it opens, one response per generation that the browser keeps. On a generated index of 4,500 units the status page went from 1.75 MB to 11.5 KB.
  - The tree leaves out framework and gem source files.
  - Folded folders hide what is under them; clearing the filter puts the folds back; an empty filter result says so in a live region.
  - **The sheet:** ☰ opens it at every width. Its header and filter stay in view while the rest scrolls. Below 960 it carries the primary nav, which the bar hides there.
  - **Below 640** the bar keeps a usable search field, and the status bar wraps instead of clipping.
  - **The trail** keeps one entry per unit, across its tabs. It never shows an empty entry, names pages from their title, and writes an action as `Controller#action` with one `#`.
  - **The peek** stays inside the code region, and Escape or ✕ returns focus to the reference that opened it.
  - **Keys:** `j` / `k` step into the page's first table from anywhere, and Shift+Slash opens the keyboard help.
  - **Expand all** reads *collapse all* while every row is open.
  - **Labels:** a toggle column names only what its rows carry.
  - **The lens:** `?lens=` renders that lens at that URL and remembers it, instead of redirecting to the bare URL; an unknown lens is ignored.
  - **Passage:** the rail links to the filter matrix and the callback ladder. The matrix can narrow to the filters that run on the page's action.
  - **Timeline:** below 640, the lane names are truncated so every dot is on screen.
  - **Hotspots:** quadrant points are named by their rank in the table, with units at one position sharing a point, so labels no longer collide.
  - **Landscape Status:** its state column fits *published*.
